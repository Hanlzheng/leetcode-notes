# 20. Valid Parentheses

## 题目

给定一个只包含 `(`、`)`、`{`、`}`、`[`、`]` 的字符串 `s`,判断该字符串是否有效。

有效字符串需满足:
1. 左括号必须用相同类型的右括号闭合;
2. 左括号必须以正确的顺序闭合;
3. 每个右括号都有一个对应的相同类型的左括号。

## 思路

括号匹配是栈的经典应用,核心是「后进先出」:

- 遍历字符串,遇到**左括号**就压入栈;
- 遇到**右括号**时,它必须和**最近一个未匹配的左括号**(即栈顶)配对。从栈中弹出栈顶,检查是否是对应的左括号;
- 用一个字典 `pairs` 把右括号映射到对应的左括号,避免写三组 `if/elif`;
- 遍历结束后,栈必须为空 —— 如果还有剩余左括号,说明它们没被闭合。

两种失败情况:
- 遇到右括号但栈为空 → 没有左括号与之配对;
- 弹出的栈顶与当前右括号不匹配 → 类型或顺序错误。

利用 `or` 的短路特性 `not stack or stack.pop() != pairs[ch]`,可以把这两种失败合并成一个判断:`not stack` 为真时直接短路,不会执行 `stack.pop()`,从而避免空栈弹出报错。

## 我踩的坑

1. **并列的 `if` 不是互斥的**:最初用了两个独立的 `if` 判断 `>=` 和 `<`,第一个分支推进指针后,第二个分支又读了被推进的数据,既会越界又会让逻辑执行两次。互斥的分支必须用 `elif/else`。
2. **空栈 pop 会抛 `IndexError`**:输入如 `")"` 时栈为空,直接 `stack.pop()` 会让程序崩溃。必须在 pop 前确认栈非空。
3. **比较方向写反**:判断不匹配应该用 `!=`,一度写成 `==`,导致「正确匹配」反而被判为失败。
4. **收尾忘了检查栈状态**:循环正常结束不代表有效。输入 `"("` 时循环跑完栈里还剩一个左括号,不能无条件 `return True`,最后必须 `return not stack`。
5. **反向多写了 `else`**:重构时给 `elif` 补了个 `else: return False`,结果「右括号成功匹配栈顶」这种好事反而触发了失败返回。匹配成功时无需任何操作,直接进入下一轮即可。

## 解法
```Python
class Solution:
    def isValid(self, s: str) -> bool:
        stack = []
        pairs = {')': '(', ']': '[', '}': '{'}
        for ch in s:
            if ch in "([{":
                stack.append(ch)
            elif not stack or stack.pop() != pairs[ch]:
                return False
        return not stack
```

## 复杂度

- **时间复杂度**:O(n),`n` 为字符串长度,每个字符只遍历一次,入栈/出栈均为 O(1)。
- **空间复杂度**:O(n),最坏情况下(如 `"((((("`)所有字符都是左括号,全部压入栈中。
